# Sprint scope changes

This log records changes to the TSEK sprint plan through **14 November 2026
(Philippine time)**. Sprint labels describe where work was planned. Merge dates
record when code entered main. Deployment and acceptance evidence are tracked
separately.

| Change | What changed and why | Evidence and status |
| --- | --- | --- |
| **Moved out of Sprint 1** | Unfinished walking-skeleton work carried into Sprint 2 or later while its original Sprint 1 issues stayed in place. The Sprint 1 record documents late issue creation, backend work starting in Sprint 2, and hosting configuration still missing during Sprint 1. | [Sprint 1 record](sprints/SPRINT_1.md) and [carryover issue #14](https://github.com/Anthonyiwnl/tsek/issues/14). Catalogue schema and API merged in [#4](https://github.com/Anthonyiwnl/tsek/pull/4) on 27 October. The requirements screen moved from fixtures to the deployed catalogue API in [#62](https://github.com/Anthonyiwnl/tsek/pull/62), merged 2 November. The first automated staging-to-production deployment was recorded on 1 November ([run 41316410179](https://github.com/Anthonyiwnl/tsek/actions/runs/41316410179)). |
| **Carried Sprint 2 work past its planned window** | The Sprint 2 plan ran from 19 to 25 October. The team continued review, deployment, and validation after that window to prove that authenticated create, read, edit, and delete worked through the hosted frontend and persisted in PostgreSQL. | [Sprint 2 retrospective review](SPRINT_2_RETROSPECTIVE_REVIEW.md). [Consultation 2 evidence](CONSULTATION_2_EVIDENCE.md) records authenticated production checks and two-account isolation after the [sign-in fix #164](https://github.com/Anthonyiwnl/tsek/pull/164). |
| **Split AI work between Sprints 2 and 3** | Sprint 2 kept the versioned response schema and backend validation. Private uploads, extraction from document text, saving analyses, and calculating the checklist stayed in Sprint 3. This let the team agree on and test the data format before connecting the provider and storage. | The Sprint 2 contract merged on 6 November ([#63](https://github.com/Anthonyiwnl/tsek/pull/63)). Private uploads, extraction, and saved checklist results merged in [#153](https://github.com/Anthonyiwnl/tsek/pull/153), [#152](https://github.com/Anthonyiwnl/tsek/pull/152), and [#154](https://github.com/Anthonyiwnl/tsek/pull/154). |
| **Limited the document analysis rollout to text** | The extraction path takes plain text. Images and scanned PDFs require a separate OCR step. A move from GPT-4.1 mini to GPT-4.1 was deferred while the team lacked comparative quality and cost evidence. | [Analysis contract and evaluation](DOCUMENT_ANALYSIS.md), [provider decision](AI_PROVIDER.md), and [synthetic evaluation PR #155](https://github.com/Anthonyiwnl/tsek/pull/155). The synthetic evaluation used mocked provider replies. |
| **Replaced demo dashboards with API records** | The Sprint 3 dashboard cleanup replaced illustrative citizen and admin records with authenticated application records, removed the demo data and old app entry point, and consolidated routing in `App.tsx`. The admin records view uses the same owner-scoped API, so the staff-wide queue and review actions remain outside this change. | [Issue #180](https://github.com/Anthonyiwnl/tsek/issues/180) and [PR #183](https://github.com/Anthonyiwnl/tsek/pull/183), merged 14 November after the [upload and analysis UI](https://github.com/Anthonyiwnl/tsek/pull/181) and [replacement and reanalysis](https://github.com/Anthonyiwnl/tsek/pull/182). |
| **Added evaluation and AI safeguards** | Sprint 3 added a synthetic model comparison and mock-based extraction evaluation so the team could compare behavior and reproduce failures without live provider calls in CI. Sprint 4 added shared request limits and bounded retries to control cost and provider failure. | [Model comparison #101](https://github.com/Anthonyiwnl/tsek/issues/101), [evaluation #155](https://github.com/Anthonyiwnl/tsek/pull/155), [failure coverage #156](https://github.com/Anthonyiwnl/tsek/pull/156), and [hardening #184](https://github.com/Anthonyiwnl/tsek/pull/184).
